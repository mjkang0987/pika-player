# 모바일 동영상 플레이어 기획서 (가칭)

> 리서치 기준일: 2026-08-21 · 범위: 로컬/네트워크 파일 기반 동영상 플레이어 앱 (VLC, MX Player, Infuse, KMPlayer 등 동일 카테고리 기준)
>
> **문서 갱신: 2026-08-25.** 3장(수익 구조)에서 유료 등급을 없앤 결정과, 그 뒤에 실제로
> 만든 것을 7장에 반영함. 이 문서는 **만들 것**이 아니라 **만든 것과 아직 아닌 것**을
> 구분해 적는다 — 앞의 것만 적혀 있으면 어디까지 왔는지 문서로는 알 수 없다.

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 목적 | 다양한 포맷의 동영상을 끊김 없이 재생하는 모바일 플레이어 앱 |
| 플랫폼 | **Android 우선** (iOS는 이후 확장 검토) |
| 사업 형태 | 개인사업자 등록 예정 (수익화 전제) |
| 타겟 | 다운로드/녹화 영상을 자주 보는 일반 사용자, 자막 시청자, 파워유저(NAS/클라우드 연동) |
| 포지셔닝 | "가볍고 광고 부담 없는 올포맷 플레이어" — Infuse류 프리미엄 감성 + VLC류 무료 진입장벽 사이 |

**참고**: Android는 팝업/플로팅 윈도우, 다양한 파일시스템 접근 등 B 항목 기능 구현이 iOS보다 자유로움 — Android 우선 전략과 궁합이 좋음 (2.B 참고).

**전제**: 스트리밍 플랫폼(자체 콘텐츠 제공)이 아니라, 사용자가 보유한 파일을 재생하는 **로컬/네트워크 플레이어** 앱으로 가정. 콘텐츠 제공형(OTT)이라면 별도 기획 필요.

## 2. 리서치 요약 — 카테고리 내 일반적인 기능

동일 카테고리 앱(VLC, MX Player, XPlayer, KMPlayer, Infuse, BS Player, MCPlayer HD Pro 등) 조사 결과, 기능은 4개 층위로 수렴함.

### A. 재생 기본 기능 (필수)
- MP4, MKV, AVI, FLV, MOV, WMV 등 대다수 포맷 지원 (변환 없이 재생)
- 하드웨어 가속 디코딩 → HD/4K 부드러운 재생
- 자막 지원: 파일 자동 매칭, 인코딩(UTF-8 등) 변경, 싱크 조정 단축키
- 제스처 컨트롤: 좌우 스와이프(탐색), 상하 스와이프(밝기/볼륨)
- 재생속도 조절, 구간 반복(A-B repeat)
- 화면 회전 / 미러 / 확대 / 자르기

### B. 편의·차별화 기능
- PiP(Picture-in-Picture) — iOS 필수 수준으로 보편화
- 팝업/플로팅 윈도우 재생 (다른 앱 위에 표시, Android 강점)
- 재생목록·라이브러리 관리, 최근 재생 이어보기
- 네트워크 연동: NAS/SMB/DLNA/UPnP 스트리밍, Wi-Fi 파일 전송, 클라우드 저장소(Drive 등)
- AirPlay/Chromecast 미러링
- 취침 예약 타이머, 나이트 모드
- 어린이 잠금(parental lock)

### C. 상위 차별화 기능 (프리미엄/AI)
- AI 업스케일링 (SD→HD/4K, 최근 트렌드로 부상)
- 색상/필터 편집, 자막 자동 생성·번역
- Dolby 오디오 등 고급 오디오 처리 (Infuse의 유료 전환 포인트)

### D. 신뢰·프라이버시
- 오프라인 완전 동작 (네트워크 불필요)
- 비공개 앨범/PIN 잠금 (개인 영상 보호)

**시사점**: A는 진입 필수 조건(없으면 즉시 이탈), B가 리텐션을 만들고, C가 유료 전환 트리거로 쓰이는 구조가 카테고리 공통 패턴임.

## 3. 수익 구조 설계

> **결정 (2026-08): 전부 무료. 유료 등급 없음.** Pro 티어·결제·기능 게이팅을 코드와 화면에서 전부 제거함. PiP 를 포함해 만든 기능은 모두 무료로 연다.

### 왜 뒤집었나

1차안은 "Free + Pro 일회성 인앱결제, 광고 없음" 이었다. **팔려던 기능이 전부 경쟁 앱에서 무료라는 것을 뒤늦게 확인해 폐기함.**

| 유료로 걸려던 기능 | 1차안 근거 | 실제 |
|---|---|---|
| 네트워크 스트리밍 (SMB/NAS) | "주력 전환 카드, 대체재가 적음" | **VLC 가 무료로 제공.** SMB·NFS·FTP·SFTP·UPnP 전부. Nova Video Player 는 NAS 탐색 + 라이브러리 색인까지 무료 |
| 비공개 폴더 / PIN | "감정에서 나오는 지불의사" | **MX Player·VLC 둘 다 무료 기본 기능** |
| PiP / 플로팅 윈도우 | "멀티태스킹 = 헤비유저 지표" | 여러 플레이어가 무료 제공. 구현도 OS 가 주는 30 줄 남짓 |

1차안의 "대체재가 적음" 은 근거 없이 쓴 문장이었다. 확인해 보니 **가장 유명한 무료 앱이 그 기능을 준다.**

### 카테고리에서 실제로 돈이 나오는 곳

| 앱 | 모델 | 파는 것 |
|---|---|---|
| VLC | 비영리 협회 + 별도 영리사(Videolabs) | **앱이 아님.** 방송사·정부 대상 컨설팅·지원 계약·SDK 라이선스 (2017 년 기준 매출 약 $117 만) |
| MX Player | 구독 | **콘텐츠.** OTT 스트리밍 서비스로 전환함. 플레이어 기능이 아님 |
| nPlayer | 선불 $4.99 일회성 | 앱 자체. **무료 티어가 없음** |
| Nova Video Player | 없음 (오픈소스) | — |

**"무료로 쓰다가 기능 때문에 결제한다" 는 경로는 이 카테고리에 사실상 없다.** 무료 경쟁자가 너무 강하다. 돈이 나오는 길은 (1) 콘텐츠를 팔거나 (2) 앱을 통째로 선불로 팔거나 (3) 앱 밖에서 버는 것뿐이고, 셋 다 지금 구조와 맞지 않는다.

### 그래서 무엇을 하는가

**결제를 열지 않는다.** VLC 대비 우위가 없는 상태에서 선불로 돌려도 팔리지 않고, 광고를 넣으면 1장 포지셔닝("광고 부담 없는 올포맷 플레이어")과 정면으로 충돌한다. 매출 0 을 받아들이고 앱 자체의 완성도로 간다.

**광고는 넣지 않는다.** 이 결정은 1차안에서 그대로 유지됨.

### 되돌리는 비용

낮지 않다. `entitlement` 모듈·`BillingRepository`·`ProScreen`·설정 화면의 Pro 섹션을 전부 지웠다. 되살리려면 git 이력에서 꺼내야 한다.

```
git log --diff-filter=D -- entitlement app/src/main/java/com/pikaworks/pikaplayer/data/billing
```

**다시 유료를 검토할 조건**: 경쟁 앱이 무료로 주지 않는 기능을 확보했을 때. 지금 목록(SMB·PiP·비공개 폴더)에는 없다. 새로 찾아야 한다.

### 기능별 티어 분류 — 폐기

전부 무료이므로 분류가 없다. 만들 기능의 우선순위는 6장 로드맵을 따른다.


### 초기 운영 비용 (Phase 1 = 광고·서버 없음 기준)

| 항목 | 비용 | 비고 |
|---|---|---|
| Google Play 개발자 등록 | **$25 (일회성)** | 사실상 유일한 확정 지출 |
| 개발 도구 (Android Studio, Kotlin, Media3) | 0 | 전부 무료·오픈소스 |
| 로컬 데이터 저장 (Room/DataStore) | 0 | 기기 내부 SQLite — **서버 DB가 아님** |
| 서버 / 백엔드 | 0 | Phase 1은 완전 오프라인 동작(2.D 항목) |
| 개인정보처리방침 호스팅 | 0 | Play 등록 시 URL 요구 → GitHub Pages 등으로 대체 |
| 크래시 리포팅 (Firebase Crashlytics) | 0 | 무료 티어로 충분 |
| 테스트 기기 | 0~ | 보유 기기 활용. 구버전/저사양 검증용 추가 기기는 선택 |
| 사업자 등록 | 0 | 등록 자체는 무료 (세무 대행은 매출 발생 후 검토) |

**로컬 저장은 필요함**: "최근 재생 이어보기 / 재생목록 / 설정"(2.B)은 앱 재시작 후에도 남아야 하므로 Room(SQLite) 또는 DataStore를 씀. 다만 이건 **기기 안에서 도는 것이라 비용이 0**이고, 서버 DB를 두자는 얘기가 아님.

### Phase 2 이후 발생하는 비용
- Play 인앱결제 수수료 15~30% (소규모 개발자 프로그램 시 15%)
- 구독 관리 인프라(영수증 검증, 환불, 해지 방어) 직접 구축 시 공수 큼 → RevenueCat 등 서드파티 활용 검토 (일정 매출까지 무료 티어)
- AI 기능(업스케일링, 자막생성)은 서버/API 비용 발생. 지금은 유료 등급이 없으므로 **원가를 댈 방법이 없다** — 만들려면 3장 결정부터 다시 봐야 한다

## 4. 사업자 등록 관련 체크리스트

3장에서 광고와 인앱결제를 모두 없앴으므로 **당장은 등록해야 할 이유가 없다.** 매출이 0인 동안에는 등록으로 얻는 것이 사실상 없다.

다만 나중에 하려면 번거로운 것이 하나 있어서 남겨 둔다 — Google Play 결제 프로필의 계정 유형이다. 아래는 그때를 위한 메모다 (세부 사항은 세무사 확인 권장 — 일반 정보임).

| 항목 | 내용 |
|---|---|
| 업태 | 서비스업 |
| 업종 | 응용소프트웨어 개발 및 공급업 (업종코드 722000 계열) — 향후 광고 대행/전자상거래 겸업 시 부업종 추가 검토 |
| Google Play 개발자 계정 유형 | 반드시 **'개인'**으로 등록 — 개인사업자는 '조직' 유형으로 결제 프로필 생성 불가 |
| 사업자등록번호(BRN) 제출 | Apple도 국내 전자상거래법 준수를 위해 개발자에게 BRN 요구 — 미입력 시 앱 비노출 가능성 있음 |
| 청년창업 세액감면 | 나이 요건 해당 시 감면 가능 — 업종 추가 시점(최초 등록 vs 추후 추가)에 따라 감면 적용 범위가 달라질 수 있어 등록 전 확인 필요 |
| 해외 정산 관련 | Google/Apple 해외 정산분에 대한 부가세·외화 입금 처리는 규모가 커지면 별도 검토 대상 |

**타임라인 제안**: 앱 출시 전 사업자 등록 완료 → Google Play 결제 프로필을 사업자 명의로 세팅 → 이후 인앱결제 활성화 순서가 가장 매끄러움 (사업자 등록 후 계정 유형 변경은 번거로움).

**지금 판단**: 등록을 미룬다. 얻는 것이 없는데 유지 부담만 생긴다. 다시 볼 시점은 결제를 붙이기로 한 때이고, 그 조건은 3장에 적어 두었다.

## 5. 기술 스택 (결정)

| 항목 | 선택 | 비고 |
|---|---|---|
| 언어 | **Kotlin 단일** | C/C++(NDK) 직접 작성 없음 — 1인 개발 공수 방어 |
| UI | Jetpack Compose | XML 대비 화면 구현 속도 우위 |
| 플레이어 | Media3(ExoPlayer) 우선 | Kotlin-first API, coroutines/Flow 친화 |
| 크로스플랫폼 | 미도입 | PiP·플로팅 윈도우·SAF 등 B 항목이 플랫폼 표면에 밀착 → 네이티브가 유리 |
| iOS 확장 | 추후 KMP 검토 | 지금은 도입하지 않음. 도메인 로직을 UI에서 분리해두는 수준만 유지 |

**"Kotlin 단일"의 범위**: 직접 작성하는 코드는 전부 Kotlin. 디코더처럼 네이티브 구현이 불가피한 영역은 **미리 빌드된 아티팩트(AAR)를 가져다 쓰는 선까지만** 허용하고, ffmpeg를 직접 빌드하거나 JNI 브릿지를 작성하는 작업은 범위에서 제외.

**주의**: 이 결정이 디코더 라이브러리 선택까지 정하지는 않음. Media3와 libVLC 모두 prebuilt 형태로 Kotlin에서만 사용 가능하므로, 선택 기준은 언어가 아니라 **포맷 커버리지 vs 라이선스·용량**임 (8장 참고).

### 실제로 쓰고 있는 값 (2026-08 기준)

| 항목 | 값 | 비고 |
|---|---|---|
| Kotlin | 2.4.10 | AGP 9 부터 Kotlin 지원이 AGP 안에 들어옴 — `kotlin.android` 플러그인을 따로 적용하면 빌드가 막힌다 |
| AGP | 9.1.0 | |
| compileSdk / targetSdk | 37 | Compose 1.12(BOM 2026.08)와 core-ktx 1.19 가 요구하는 값 |
| minSdk | 24 | |
| Compose | BOM 2026.08.00 | |
| 플레이어 | Media3 (ExoPlayer) | |
| 로컬 DB | Room 2.8.4 (KSP 2.3.11) | 스키마 v3. `app/schemas/` 에 JSON 으로 남긴다 |
| 설정 저장 | DataStore Preferences | |
| 썸네일 | Coil + VideoFrameDecoder | |

**순수 Kotlin 모듈 분리**: `:subtitle`(자막 파싱·인코딩 감지), `:vault`(PIN 해시·시도 제한). 안드로이드 의존이 없어 JVM 단위 테스트로 검증한다 — 이 두 곳이 틀리면 자막이 깨지거나 잠금이 뚫리는데, 기기를 띄워 확인할 성질이 아니다.

## 6. 로드맵 (Android, 1인 개발 기준)

3장에서 유료 등급을 없앴으므로 **Phase 를 나누던 기준이 사라졌다.** 원래 경계는 "무엇을 무료로 주고 무엇을 잠글 것인가" 였는데, 잠글 것이 없어졌기 때문이다. 지금 기준은 **출시에 필요한가**뿐이다.

| Phase | 범위 | 상태 |
|---|---|---|
| Phase 1 | A 전체 + 자막 + B 중 만든 것(PiP·비공개 폴더·재생목록·어린이 잠금) | **기능 완료.** 출시 준비 항목만 남음 (7.3) |
| Phase 2 | 네트워크 소스(SMB/NAS), 태블릿 2-pane, 그리드 보기 | 미착수 |
| Phase 3 | C(AI 업스케일링·자막 자동생성) | **원가를 댈 방법이 없다** — 유료 등급이 없으므로 3장 결정부터 다시 봐야 한다 |

**PiP 는 Phase 1 에 들어왔다.** 원래는 "Pro 기능이라 결제 수단이 없는 Phase 1 에서는 넣을 수 없다" 는 이유로 빠져 있었다. 유료 등급을 없앴으므로 그 이유가 통째로 사라졌고, 구현은 OS 가 주는 것에 얹는 수준이라 미룰 까닭이 없었다.

**게이팅 인터페이스는 만들지 않았다.** "나중에 결제를 붙일 때를 대비해 판단 지점 하나만 미리 분리해 두자" 는 1차안의 제안은 폐기했다. 붙일 결제가 없는 동안에는 늘 허용을 반환하는 껍데기일 뿐이고, 껍데기는 왜 있는지 잊힌 채로 남는다. 다시 유료를 검토하게 되면 그때 넣는다 — 3장에 적었듯 그 조건은 "경쟁 앱이 무료로 주지 않는 기능을 확보했을 때" 이고, 지금 목록에는 없다.

### 7.2 기능 단위

**재생 코어 (S3)** ✅
- Media3 플레이어 구성, 하드웨어 가속 디코딩
- 제스처: 좌우 스와이프(탐색), 좌측 상하(밝기), 우측 상하(볼륨), 더블탭(±10초)
- 컨트롤: 재생/일시정지, 10초 전/후, 시크바, 재생속도(시트), 자막, 화면비, 반복, 전체화면, 작은 창, 잠금
- 이전 영상 · 다음 영상 버튼 — 대기열에 있을 때만 만든다. 눌러도 아무 일이 없는 버튼은 고장으로 읽힌다
- 끝난 영상에서 재생을 누르면 처음부터. 97% 넘게 본 영상은 이어보기를 건너뛰고 처음부터 튼다
- **전체화면은 영상 비율로 갈린다.** 가로 영상은 눕혀야 커지고, 세로 영상은 눕히면 좌우가 다 검게 남아 오히려 작아진다. 전에는 전체보기와 가로가 한 덩어리였다
- **자동회전 연동**: 시스템 자동회전이 켜져 있으면 눕힐 때 전체화면 진입. 앱 내 방향 잠금은 시스템 설정보다 우선 (누워서 보는 사용자)
- 자막은 영상 프레임 안쪽 또는 레터박스 띠 — 설정에서 고른다
- ⬜ **핀치 확대** — 안 만듦. 화면비 버튼(맞춤/채움/늘이기)이 같은 일을 하고, 재생 중 두 손가락 몸짓은 밝기·볼륨 스와이프와 얽힌다
- ⬜ **백그라운드 오디오 / MediaSession 알림 컨트롤** — 안 만듦. 화면 밖으로 나가면 작은 창(PiP)이 따라 나오는 쪽을 먼저 붙였다. 소리만 남기는 경로는 별개이므로 Phase 2

**반복 · 순서 (S3)** ✅
- 반복 버튼이 시트를 연다: 한 편 반복 / 목록 반복 / 랜덤 / 자동 재생
- 넷 다 "이 영상이 끝나면 무엇이 일어나는가" 한 가지 질문의 답이라 한데 묶는다. 흩어 놓으면 서로 어떻게 맞물리는지 알기 어렵다
- 목록 반복과 랜덤은 **목록을 통째로 튼 경우에만** 뜬다(재생목록·폴더·최근·이어보기). 보관함에서 한 편을 누른 대기열은 "기기의 모든 영상" 이라, 거기서 섞는 것은 순서를 흐트러뜨리는 것이 아니라 그냥 아무 영상이나 트는 것이 된다
- 랜덤은 원래 순서를 따로 들고 있다가 끄면 되돌린다
- 자동 재생 토글은 설정의 값을 그대로 읽고 쓴다. 두 곳에 따로 두면 서로 다른 말을 하게 된다

**A-B 구간 반복 (S3)** ✅
- 시간 줄의 A-B 버튼으로 시작점 → 끝점 → 해제. 시크바에 표시를 남긴다

**다음 영상 목록 (S3 하단)** ✅
- **대기열은 "어느 목록에서 눌렀는가"** 로 정해진다. 튼 화면의 목록이 그대로 대기열이 되고, 지금 영상 뒤에 오는 것들이 다음 영상이다
- 보관함만 예외로 같은 폴더로 한 번 더 거른다 — 거기 목록은 기기의 모든 영상이라 폴더가 실질적인 단위다
- 세로에서만 노출. 전체화면에서는 영상이 화면을 채우므로 자리가 없다
- 다음 영상이 없으면 그 자리에 "다음 영상이 없습니다" 를 남긴다. 영역이 조용히 사라지면 목록이 있었는지조차 알 수 없다

**작은 창 (PiP)** ✅
- 시스템 컨트롤에 재생/일시정지. 창 안에는 우리 화면이 없어서 시스템이 그려 주는 버튼뿐이다
- 설정의 '자동 작은 창' 을 켜면 홈으로 나갈 때 따라 나온다. API 31+ 는 시스템이 제스처 도중에 알아서 넘겨 주므로 우리는 손을 뗀다
- 지원하지 않는 기기에서는 버튼 자체를 만들지 않는다

**라이브러리 (S1·S2)** ✅
- MediaStore 스캔 + SAF 폴더 선택 두 갈래. 권한을 거부한 사용자는 SAF 로만 앱을 쓴다
- **ContentObserver 로 기기 목록 변화를 그 자리에서 받는다.** 전에는 화면에 다시 들어올 때만 다시 읽어서, 앱을 켜 둔 채 파일을 내려받으면 앱이 못 찾는 것처럼 보였다
- 당겨서 새로고침, 정렬(이름/날짜/크기/길이), 거르기 탭(영상/자막/보던 중/안 봄)
- 줄 오른쪽 ⋯ 메뉴 → 재생목록에 담기 / 기기에서 삭제. 길게 누르면 바로 담기
- 재생 위치 저장 및 이어보기 — Room
- ⬜ **리스트·그리드 전환** — 안 만듦. 7.2.1 참고

**재생목록** ✅
- 여러 폴더에 흩어진 영상을 한 줄로 묶는다. 목록마다 이름·순서를 갖는다
- 편집은 완료·취소가 있는 한 판이다. 순서 바꾸기와 빼기를 곧바로 저장하지 않고 화면이 임시로 들고 있다가 완료에서 한 번에 넘긴다 — 한 칸 옮길 때마다 저장하면 취소가 되돌릴 것이 남지 않는다
- 저장은 빼기와 자리 매기기를 한 트랜잭션으로. 따로 부르면 중간에 앱이 죽었을 때 뺀 것만 반영되고 순서는 옛것으로 남는다
- 목록 삭제는 목록 **밖**(재생목록 화면)에서 한다. 손보러 들어온 자리에서 목록이 통째로 사라지는 것은 층이 맞지 않는다
- ⬜ **끌어서 순서 바꾸기** — 만들었다가 지웠다. 위·아래 버튼으로 되돌림

**비공개 폴더 · 어린이 잠금** ✅
- 고른 폴더를 목록에서 감춘다. **파일을 지우거나 암호화하지 않는다** — 파일 관리자로는 그대로 보인다. 개인정보 처리방침에도 그렇게 적었다
- PIN 은 PBKDF2-HMAC-SHA256 해시와 소금으로만 기기에 남는다. 서버도 계정도 없어 만든 사람도 되돌릴 수 없다
- 실질적인 방어는 해시 강도가 아니라 **시도 제한**이다. 4번까지는 그냥 틀릴 수 있고, 그 뒤로는 30초를 기다린다(늘어나지 않는다). 상태는 기기에 저장한다 — 앱을 껐다 켜서 초기화되면 막는 의미가 없다
- 어린이 잠금은 같은 PIN 을 쓴다. 잠긴 동안에는 뒤로가기로도 나갈 수 없다

**자막 (S4)** ✅
- 동일 파일명 기준 자막 자동 매칭(.srt/.smi/.ass/.vtt)
- **인코딩 감지 및 수동 변경** — 국내 파일은 `.smi` + CP949 조합이 흔해 실패 시 이탈로 직결되는 지점. 자동 감지 실패에 대비한 수동 변경 경로 필수
- 싱크 오프셋 조정(±0.5초 단위), 글자 크기·색·외곽선/그림자 설정
- **표시 위치**: 기본값은 **영상 프레임 하단 고정**. 설정에서 상하 오프셋 조절, 그리고 레터박스(영상 위아래 검은 띠) 영역으로 내리는 옵션 제공 — 시네마스코프 영상에서 화면을 가리지 않으려는 수요가 있음
- 컨트롤이 표시되는 동안에는 자막이 시크바를 가리지 않도록 자동으로 올라가고, 컨트롤이 숨으면 기본 위치로 복귀

**자막 상태 표시 규칙**

플레이어의 자막 칩/라벨은 "지금 무엇이 나오고 있는가"를 그대로 보여줌. 로컬 플레이어는 자막 출처가 두 갈래이고 각각 알 수 있는 정보가 다르므로 상태별로 표기를 나눔.

| 상태 | 표기 | 비고 |
|---|---|---|
| 외부 자막 파일 재생 중 | `자막 · SRT` (형식명) | **가장 흔한 경우.** `.srt`/`.smi` 파일에는 언어 정보가 없어 앱이 한국어인지 알 수 없음 |
| 내장 트랙 재생 중 (언어 태그 있음) | `한국어` | MKV 등은 트랙에 언어 코드가 있어 언어명 표시 가능 |
| 내장 트랙 재생 중 (언어 태그 없음) | `트랙 1` | |
| 자막이 여러 개일 때 | 선택된 항목명 | 탭하면 선택 목록 시트 |
| 자막 끔 | `자막 끔` | 아이콘 비활성 색 |
| 자막 없음 | `자막 없음` | 탭하면 자막 파일 직접 열기로 연결 |

**주의**: 초안 시안의 `한국어 자막` 표기는 언어를 알 수 있는 경우에만 성립함. 파일명 옆에 놓인 `.srt`는 내용을 해석하기 전에는 언어를 알 수 없으므로, 기본 표기는 **형식명(SRT/SMI/ASS)** 을 쓰고 언어는 확인 가능할 때만 노출. 라이브러리 목록의 `SRT`/`SMI` 배지와 같은 규칙.

**설정 (S6)** ✅

| 섹션 | 항목 |
|---|---|
| 라이브러리 | 자동 작은 창 / 비공개 폴더 / 어린이 잠금 |
| 재생 | 기본 재생속도 / 이어보기 / 다음 영상 자동 재생 |
| 자막 | 기본 인코딩(자동 감지) / 글자 크기 / 표시 위치 |
| 제스처 | 밝기·볼륨 스와이프 / 더블탭 10초 이동 |
| 화면 | 테마(다크·라이트·시스템) / 자동회전 연동 |
| 정보 | 버전 / 오픈소스 라이선스 |

- 제스처와 자동 재생은 **끌 수 있어야 함** — 의도치 않은 탐색이나 다음 영상 재생을 싫어하는 사용자가 일정 비율 존재
- 화면 제목은 목록과 함께 밀려 올라가지 않는다. 어느 화면에 있고 어디로 나가는지는 스크롤 위치와 상관없이 늘 보여야 한다
- 어린이 잠금은 PIN 이 없으면 켤 수 없다. 그때는 스위치 대신 **PIN 을 정하러 가는 줄**을 보여 준다 — 눌러도 안 켜지는 스위치는 고장으로 읽힌다
- 오픈소스 라이선스 고지는 선택이 아님. 디코더 라이브러리(8장 참고) 선택에 따라 고지 의무가 발생함

**기반**
- 권한 처리 (Android 13+ `READ_MEDIA_VIDEO`, 이전 버전 분기) ✅
- **권한 거부 대비 경로 필수** — 저장소 권한은 거절률이 높음. 거부해도 SAF로 폴더를 직접 고르면 앱을 쓸 수 있어야 하고, 이 경로가 없으면 거부 즉시 이탈 ✅
- 설정 영속화 (DataStore) ✅
- 파일 삭제는 `MediaStore.createDeleteRequest` 로 시스템 확인을 거친다(API 30+). 앱이 조용히 지우지 않는다 ✅
- ❌ **기능 접근 판단 인터페이스(게이팅)** — 6장 참고. 붙일 결제가 없어 폐기
- ⬜ **크래시 리포팅** — 안 붙였다. Crashlytics 는 기기 식별자와 사용 정보를 구글로 보내는데, 개인정보 처리방침에 "네트워크로 아무것도 보내지 않는다" 고 적었고 앱은 `INTERNET` 권한 자체를 요청하지 않는다. 넣으려면 그 약속부터 고쳐야 하므로 지금은 Play Console 의 ANR·크래시 집계로 대신한다

### 7.2.1 화면 크기 대응 (태블릿)

**Phase 1 목표는 "태블릿에서 깨지지 않는 것"까지.** 태블릿 전용 레이아웃 최적화는 Phase 2로 미룸.

| 구간 | 대응 |
|---|---|
| ~600dp (일반 폰) | 기준 레이아웃 |
| 600dp~ (소형 태블릿·폴더블 펼침) | ⬜ 라이브러리 목록을 2열 그리드로 — **안 만듦.** 지금은 폭이 넓어져도 한 줄 목록 그대로다 |
| 840dp~ (일반 태블릿) | ⬜ 폴더 트리 + 목록 2-pane (Phase 2) |

- ⬜ Compose의 `WindowSizeClass` 분기는 아직 넣지 않았다. 지금 대응은 "폭에 맞춰 늘어나되 깨지지는 않는다" 수준이고, 목표였던 그 선에는 닿아 있다. 별도 앱이 아니라 **하나의 APK로 대응**하는 전제는 유지
- ✅ 좁은 화면 대응은 들어갔다. PIN 숫자판은 남은 높이에 맞춰 키 크기를 44~72dp 사이에서 고른다 — 고정 크기로 두었더니 작은 화면에서 하단 네비게이션에 잘렸다
- 플레이어 화면은 태블릿에서도 구조 변경 불필요 — 영상이 중앙, 컨트롤이 하단인 형태가 그대로 성립
- 주의: 태블릿은 **가로가 기본 방향**인 기기가 많음. 세로 기준으로만 만들면 첫 실행부터 어색해지므로 Phase 1에서도 가로 레이아웃 검증은 필요

### 7.3 출시 전 반드시

기능 쪽 완료 기준은 채웠다 — 주요 포맷이 실기기에서 하드웨어 가속으로 재생되고, 자막이 자동으로 붙고 깨지면 인코딩으로 복구되며, 앱을 껐다 켜도 이어보기가 동작하고, 네트워크 없이 전부 돈다.

남은 것은 **내보내는 일에 관한 것**뿐이다.

| # | 항목 | 상태 |
|---|---|---|
| 1 | 런처 아이콘 | ✅ 적응형 + 구형 PNG + 테마 아이콘 + 스토어 512 |
| 2 | **Room 마이그레이션** | ✅ 버전을 가리지 않고 지우던 것을 1·2(개발 빌드)에서만 지우게 좁힘. 스키마를 `app/schemas/` 로 남긴다 |
| 3 | **릴리스 빌드 검증** | ⬜ `isMinifyEnabled = true` 인데 한 번도 릴리스로 빌드해 보지 않았다. R8 이 Room·Media3 의 리플렉션 경로를 깎아서 디버그에서는 되고 릴리스에서 죽는 일이 흔하다 |
| 4 | **서명 keystore** | ⬜ 만들고 백업까지. 잃어버리면 그 앱은 영영 업데이트할 수 없다 |
| 5 | 개인정보 처리방침 URL | ⬜ 문서는 `docs/privacy.md`(한국어)·`docs/privacy.en.md`(영어). GitHub Pages 를 켜야 URL 이 생긴다 |
| 6 | 스토어 등록 정보 | ⬜ 스크린샷, 짧은/긴 설명, 카테고리 |
| 7 | 버전 | ⬜ 지금 `versionCode 1` / `versionName 0.1.0` |

**2번이 왜 출시 차단인가**: `fallbackToDestructiveMigration` 은 스키마가 안 맞으면 테이블을 지우고 새로 만든다. 개발 중에는 편하지만 이대로 내보내면 **다음 업데이트에서 컬럼 하나만 바꿔도** 사용자의 이어보기 기록·재생목록·비공개 폴더 목록이 말없이 사라진다. 지금은 3부터 맞는 마이그레이션이 없으면 앱이 열리다 죽는다 — 데이터를 지우고 계속 도는 것보다 내보내기 전에 알아차리는 편이 낫다.

### 7.4 디자인 토큰 (확정)

키컬러는 **초록 쪽으로 튼 시안**(hue 약 170°, 청록/터콰이즈 계열). 채도는 의도적으로 낮춤 — 재생 화면과 목록에서 강조색이 콘텐츠보다 튀지 않도록. 중성색도 순회색 대신 같은 방향으로 미세하게 틀어 톤을 맞춤.

| 토큰 | 다크 | 라이트 | 비고 |
|---|---|---|---|
| 배경 | `#0c0c0e` | `#ffffff` | |
| 표면(정렬바·하단바) | `#101614` | `#eafbf8` | 라이트에서 전부 흰색이면 경계가 사라져 옅은 틴트로 층 분리. 시안의 `#f5fbf9` 는 실기기에서 층이 거의 안 보여 채도를 올린 값 |
| **떠 있는 면(다이얼로그·바텀시트)** | `#101614` | `#ffffff` | 위 표면 값을 쓰면 상자 전체가 초록으로 보인다 — 그 값은 화면에 **깔리는** 띠를 갈라 보이게 하려고 채도를 올린 것이라 떠 있는 상자에는 맞지 않는다. 다크는 반대로 배경이 이미 검정이라 표면 값을 그대로 쓴다 |
| 본문 텍스트 | `#e8f3ef` | `#0f1614` | |
| 보조 텍스트 | `#8fa6a1` | `#5a6e69` | |
| 메타 텍스트 | `#7d9691` | `#647a75` | |
| 흐린 텍스트 | `#647a75` | `#7d908b` | |
| **키컬러** | `#5cc7b4` | `#267365` | 초록 쪽으로 튼 시안(hue 약 170°), 채도를 낮춘 값. 라이트는 흰 배경 대비 확보를 위해 더 어두운 값(5.6:1) |
| 구분선 | `#1e2826` | `#e2eeea` | |
| 칩 테두리 | `#2a3734` | `#d5e4df` | |
| 진행률 칩 테두리 | `#2a4f47` | `#b3d5cc` | |
| **썸네일 위 오버레이** | `#5cc7b4` / 흰색 | **다크와 동일** | 진행 바·재생시간 배지는 어두운 영상 위에 얹히므로 앱 테마와 무관하게 항상 밝은 값 사용. 라이트 테마 값을 쓰면 썸네일에 묻혀 보이지 않음 |

**레이아웃 확정**: 헤더 → **이어보기 가로 캐러셀(최대 10개)** → 거르기 탭 → 정렬 + 저장소 용량 → 목록 → 하단 네비.

**상단 탭은 이동이 아니라 거르기다.** 시안에는 영상 / 폴더 / 최근 / 자막 이 있었는데 폴더와 최근은 하단 네비게이션과 정확히 같은 곳으로 간다. 같은 화면에 두 개의 길을 두면 어느 쪽이 지금 위치인지 흐려진다. 그래서 **영상 / 자막 / 보던 중 / 안 봄** 으로 정리했다. 자막은 시안에 있었고 다른 데서 갈 수 없는 유일한 항목이라 남겼다.

**목록 줄 썸네일은 92×52dp 하나로 고정**. 보관함·폴더·재생목록·담기 시트·다음 영상이 같은 값을 본다. 화면마다 적어 두었더니 68 에서 92 까지 제각각이 됐다.

**이어보기 진행 표시**: 썸네일 하단 진행 바 + "38분 남음" 텍스트를 함께 노출. 목록 행에서도 같은 정보를 진행률 칩(`62%`)으로 반복 노출함.
