# 모바일 동영상 플레이어 기획서 (가칭)

> 리서치 기준일: 2026-08-21 · 범위: 로컬/네트워크 파일 기반 동영상 플레이어 앱 (VLC, MX Player, Infuse, KMPlayer 등 동일 카테고리 기준)

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 목적 | 다양한 포맷의 동영상을 끊김 없이 재생하는 모바일 플레이어 앱 |
| 플랫폼 | **Android 우선** (iOS는 이후 확장 검토) |
| 사업 형태 | 개인사업자 등록 예정 (수익화 전제) |
| 타겟 | 다운로드/녹화 영상을 자주 보는 일반 사용자, 자막 시청자, 파워유저(NAS/클라우드 연동) |
| 포지셔닝 | "가볍고 광고 부담 없는 올포맷 플레이어" — Infuse류 프리미엄 감성 + VLC류 무료 진입장벽 사이 |

**참고**: Android는 팝업/플로팅 윈도우, 다양한 파일시스템 접근 등 B 항목 기능 구현이 iOS보다 자유로움 — Android 우선 전략과 궁합이 좋음 (2.B 참고).

**전제**: 스트리밍 플랫폼(자체 콘텐츠 제공)이 아니라, 사용자가 보유한 파일을 재생하는 **로컬/네트워크 플레이어** 앱으로 가정. 콘텐츠 제공형(OTT)이라면 별도 기획 필요.

## 2. 리서치 요약 — 카테고리 내 일반적인 기능

동일 카테고리 앱(VLC, MX Player, XPlayer, KMPlayer, Infuse, BS Player, MCPlayer HD Pro 등) 조사 결과, 기능은 4개 층위로 수렴함.

### A. 재생 기본 기능 (필수)
- MP4, MKV, AVI, FLV, MOV, WMV 등 대다수 포맷 지원 (변환 없이 재생)
- 하드웨어 가속 디코딩 → HD/4K 부드러운 재생
- 자막 지원: 파일 자동 매칭, 인코딩(UTF-8 등) 변경, 싱크 조정 단축키
- 제스처 컨트롤: 좌우 스와이프(탐색), 상하 스와이프(밝기/볼륨)
- 재생속도 조절, 구간 반복(A-B repeat)
- 화면 회전 / 미러 / 확대 / 자르기

### B. 편의·차별화 기능
- PiP(Picture-in-Picture) — iOS 필수 수준으로 보편화
- 팝업/플로팅 윈도우 재생 (다른 앱 위에 표시, Android 강점)
- 재생목록·라이브러리 관리, 최근 재생 이어보기
- 네트워크 연동: NAS/SMB/DLNA/UPnP 스트리밍, Wi-Fi 파일 전송, 클라우드 저장소(Drive 등)
- AirPlay/Chromecast 미러링
- 취침 예약 타이머, 나이트 모드
- 어린이 잠금(parental lock)

### C. 상위 차별화 기능 (프리미엄/AI)
- AI 업스케일링 (SD→HD/4K, 최근 트렌드로 부상)
- 색상/필터 편집, 자막 자동 생성·번역
- Dolby 오디오 등 고급 오디오 처리 (Infuse의 유료 전환 포인트)

### D. 신뢰·프라이버시
- 오프라인 완전 동작 (네트워크 불필요)
- 비공개 앨범/PIN 잠금 (개인 영상 보호)

**시사점**: A는 진입 필수 조건(없으면 즉시 이탈), B가 리텐션을 만들고, C가 유료 전환 트리거로 쓰이는 구조가 카테고리 공통 패턴임.

## 3. 수익 구조 설계

카테고리 내 관측되는 모델은 크게 4가지이며, 대부분 **프리미엄(Freemium) + 인앱결제** 조합을 채택함 (Infuse, MCPlayer HD Pro 사례).

| 모델 | 방식 | 이 카테고리에서의 사례 | 장단점 |
|---|---|---|---|
| 광고형 | 배너/전면/리워드 광고 (AdMob 등) | 무료 플레이어 다수 | 진입장벽 낮음, but 재생 중 광고는 UX 저해 → 재생 화면 자체보다 진입/종료 시점 배치가 관건 |
| 프리미엄 구독 | 기본 무료, 구독 시 광고 제거+고급기능 | Infuse (Dolby 오디오, 클라우드 스트리밍) | 반복 수익, 전환율 관리 필요 |
| 일회성 인앱결제 | Pro 버전 단건 구매 | MCPlayer HD Pro, BS Player Pro | 결제 저항 낮음(구독 대비), but LTV 낮음 |
| 하이브리드 | 광고(무료) + Pro 구매로 광고 제거·기능 해제 | 다수 안드로이드 플레이어 | 가장 흔한 조합, 세그먼트별 대응 가능 |

### 추천 구조 (결정: 광고 없이 진행)

**광고는 도입하지 않음.** 초안의 "진입/종료 시점 전면 광고"는 철회함. 재생 앱에서 광고는 UX 저해가 크고, 1장 포지셔닝("광고 부담 없는 올포맷 플레이어")과 정면으로 충돌하기 때문. 수익은 **Pro 인앱결제 단일 경로**로 감.

1. **Free**: 기본 재생(A 항목 전체) — 광고 없음. 기능 제한만으로 Pro 유도
2. **Pro (일회성 인앱결제 — 확정)**: B 항목 해제 — **PiP·플로팅 윈도우**, 네트워크 연동(NAS/SMB/클라우드), 재생목록 관리 등
3. **Pro+ (구독 — 확정)**: C 항목(AI 업스케일링, 자막 자동 생성 등) — 서버 연산 비용이 드는 기능이라 구독형이 자연스러움
4. 체험은 별도 상품 없이 **Free 티어 자체가 무기한 체험판** 역할 (재생 품질·자막 호환성을 결제 전에 검증 가능)

**결제 방식 결정 근거 (일회성 vs 구독)**

| 판단 축 | 결론 |
|---|---|
| 원가 구조 | Pro 기능은 전부 온디바이스로 서버 비용 0 → 반복 과금의 명분이 없음. "서버도 안 쓰는데 왜 매달 내냐"는 유틸리티 앱 구독 전환의 대표적 역풍 지점 |
| 카테고리 관행 | MCPlayer HD Pro·BS Player Pro 등 동종 유료 플레이어는 대체로 일회성. Infuse가 구독인 것은 클라우드 스트리밍 등 지속 비용이 실재하기 때문 |
| 운영 부담 | 구독은 갱신·해지 방어·결제 실패 복구·영수증 검증 라이프사이클이 따라옴. 저가일수록 관리 부담 대비 수익이 얇아짐 (1인 개발 기준 부담) |
| 되돌리기 비용 | 일회성 → 구독 추가는 쉬우나, 구독 → 일회성 전환은 기존 구독자 처리 때문에 번거로움 |
| 무료체험 | Play 무료체험은 구독 상품 전용이라 일회성에서는 불가. 단 **Free 티어가 그 역할을 대체**하므로 손실이 크지 않음 |

**원칙**: 온디바이스 기능 = 일회성, 서버 연산 기능 = 구독. 사용자에게 "매달 내는 것은 서버를 쓰는 기능뿐"으로 설명됨.

**선택지 (필요 시)**: Pro 기능 N일 체험이 필요하면 결제 상품이 아니라 **앱 내부 플래그로 자체 구현** 가능 (Play 정책과 무관). 단 로컬 저장이므로 재설치 시 리셋되는 허점이 있고, 서버 없이는 차단이 어려움 — 소규모 단계에서 감수 가능한 수준으로 판단.

**트레이드오프**: Phase 1은 수익 경로가 아예 없음(매출 0). 대신 리뷰 평점과 초기 리텐션을 방어하고, Phase 2의 Pro 전환 모수를 키우는 데 집중하는 구조.

### 기능별 티어 분류 (1차안)

**분류 원칙**
1. **Free만으로도 "쓸 만한 플레이어"여야 함** — 광고가 없어 Free 사용자의 직접 수익은 0. 그럼에도 Free를 넉넉히 두는 이유는 리뷰 평점과 Pro 전환 모수가 유일한 자산이기 때문.
2. **재생 자체는 절대 막지 않음** — 포맷·코덱·자막 표시를 게이팅하면 앱의 존재 이유가 사라지고 "돈 내야 영상이 나온다"는 리뷰가 붙음.
3. **Pro는 "더 많이 쓰는 사람"에게 걸림** — 파일이 많고(라이브러리), 기기가 여럿이고(네트워크), 오래 쓰는(멀티태스킹) 사용자.

#### Free

| 기능 | 출처 | 근거 |
|---|---|---|
| 전 포맷 재생 + 하드웨어 가속 | A | 카테고리 진입 조건. 게이팅하면 앱 자체가 무의미 |
| 자막 표시·자동 매칭·인코딩 변경·싱크 조정 | A | 국내 사용자에게 자막은 필수재. 특히 인코딩(CP949 등) 변경을 막으면 "자막 깨져서 못 봄"이 됨 |
| 제스처(탐색/밝기/볼륨), 재생속도, 회전·미러·확대·자르기 | A | 기본 조작. 여기서 과금하면 조작감 자체가 인질이 됨 |
| 최근 재생 이어보기 | B | 기본 기대치. 없으면 불편이 아니라 결함으로 읽힘 |
| 로컬 폴더 탐색 + 단일 재생목록 | B | 로컬 플레이어의 최소 사용 흐름 |
| 나이트 모드, 취침 예약 타이머 | B | 지불의사는 낮고 호감도만 큼 → 무료로 줘서 평점 방어 |
| 완전 오프라인 동작 | D | 포지셔닝의 핵심. 과금 대상이 아님 |

#### Pro (일회성 인앱결제 또는 저가 구독)

| 기능 | 출처 | 근거 |
|---|---|---|
| **네트워크 스트리밍 (SMB/NAS/DLNA/UPnP)** | B | **주력 전환 카드.** NAS 운용자는 지불의사가 명확하고 대체재가 적음 |
| **PiP / 플로팅 윈도우** | B | 멀티태스킹 사용 = 헤비유저 지표. 카테고리 내 유료 게이트로 보편적 |
| **비공개 폴더 / PIN 잠금** | D | 지불의사가 감정(개인 영상 보호)에서 나와 전환 기여가 클 것으로 봄 |
| 클라우드 연동 (Drive 등) | B | 파워유저 대상, 구현 공수 대비 과금 정당성 확보 |
| Wi-Fi 파일 전송 | B | PC↔폰 전송 수요. 무료 대체재가 번거로움 |
| Chromecast 송출 | B | TV 시청 시나리오 |
| 어린이 잠금 (parental lock) | B | 부모 세그먼트의 명확한 지불 동기 |
| 다중 재생목록 / 고급 정렬·폴더 규칙 | B | 라이브러리가 큰 사용자에게만 가치 발생 |
| A-B 구간 반복 | A | A 항목이지만 학습·연습 용도라 일반 시청자와 분리됨. **전환 기여가 약해 Free로 내려도 무방** |

#### Pro+ (구독)

| 기능 | 출처 | 근거 |
|---|---|---|
| AI 업스케일링 | C | 서버 연산 비용이 사용량에 비례 → 구독이 유일하게 원가 방어 가능 |
| 자막 자동 생성·번역 | C | API 비용 발생 |
| 색상/필터 편집 | C | 서버 불필요 → **Pro로 내려도 되는 항목.** 구독 가치가 얇으면 Pro 쪽으로 이동 검토 |
| 고급 오디오 처리 (Dolby 등) | C | 라이선스 비용이 별도로 붙어 원가 구조 확인 후 판단 |

**전환 설계 메모**
- Pro의 실질 주력은 **네트워크 연동 + PiP + 비공개 폴더** 3개. 나머지는 "Pro 사면 이것도 딸려온다" 수준의 부가 가치로 배치.
- **광고가 없으므로 "광고 제거"를 팔 수 없음.** 광고형 앱은 광고 제거만으로도 결제 이유가 서지만, 이 앱은 순수하게 기능 차이로만 설득해야 함 → Free/Pro 경계가 광고형보다 더 선명해야 하고, Free에 기능을 더 얹을 때마다 전환 근거가 줄어든다는 점에 유의.

### 초기 운영 비용 (Phase 1 = 광고·서버 없음 기준)

| 항목 | 비용 | 비고 |
|---|---|---|
| Google Play 개발자 등록 | **$25 (일회성)** | 사실상 유일한 확정 지출 |
| 개발 도구 (Android Studio, Kotlin, Media3) | 0 | 전부 무료·오픈소스 |
| 로컬 데이터 저장 (Room/DataStore) | 0 | 기기 내부 SQLite — **서버 DB가 아님** |
| 서버 / 백엔드 | 0 | Phase 1은 완전 오프라인 동작(2.D 항목) |
| 개인정보처리방침 호스팅 | 0 | Play 등록 시 URL 요구 → GitHub Pages 등으로 대체 |
| 크래시 리포팅 (Firebase Crashlytics) | 0 | 무료 티어로 충분 |
| 테스트 기기 | 0~ | 보유 기기 활용. 구버전/저사양 검증용 추가 기기는 선택 |
| 사업자 등록 | 0 | 등록 자체는 무료 (세무 대행은 매출 발생 후 검토) |

**로컬 저장은 필요함**: "최근 재생 이어보기 / 재생목록 / 설정"(2.B)은 앱 재시작 후에도 남아야 하므로 Room(SQLite) 또는 DataStore를 씀. 다만 이건 **기기 안에서 도는 것이라 비용이 0**이고, 서버 DB를 두자는 얘기가 아님.

### Phase 2 이후 발생하는 비용
- Play 인앱결제 수수료 15~30% (소규모 개발자 프로그램 시 15%)
- 구독 관리 인프라(영수증 검증, 환불, 해지 방어) 직접 구축 시 공수 큼 → RevenueCat 등 서드파티 활용 검토 (일정 매출까지 무료 티어)
- AI 기능(업스케일링, 자막생성)은 서버/API 비용 발생 → Pro+ 등급으로 분리해 원가 방어

## 4. 사업자 등록 관련 체크리스트

수익화(광고+인앱결제)를 전제로 하면 사업자 등록은 선택이 아니라 필수 트랙. 일반적인 앱 개발 사업자 등록 시 확인 포인트는 다음과 같음 (세부 사항은 세무사 확인 권장 — 아래는 일반 정보임).

| 항목 | 내용 |
|---|---|
| 업태 | 서비스업 |
| 업종 | 응용소프트웨어 개발 및 공급업 (업종코드 722000 계열) — 향후 광고 대행/전자상거래 겸업 시 부업종 추가 검토 |
| Google Play 개발자 계정 유형 | 반드시 **'개인'**으로 등록 — 개인사업자는 '조직' 유형으로 결제 프로필 생성 불가 |
| 사업자등록번호(BRN) 제출 | Apple도 국내 전자상거래법 준수를 위해 개발자에게 BRN 요구 — 미입력 시 앱 비노출 가능성 있음 |
| 청년창업 세액감면 | 나이 요건 해당 시 감면 가능 — 업종 추가 시점(최초 등록 vs 추후 추가)에 따라 감면 적용 범위가 달라질 수 있어 등록 전 확인 필요 |
| 해외 정산 관련 | Google/Apple 해외 정산분에 대한 부가세·외화 입금 처리는 규모가 커지면 별도 검토 대상 |

**타임라인 제안**: 앱 출시 전 사업자 등록 완료 → Google Play 결제 프로필을 사업자 명의로 세팅 → 이후 인앱결제 활성화 순서가 가장 매끄러움 (사업자 등록 후 계정 유형 변경은 번거로움).

**단, 광고 제외 결정으로 Phase 1은 매출이 0이므로** 등록을 Phase 2 직전으로 미루는 선택지도 성립함. "등록을 미뤄 얻는 것(없음에 가까움) vs 계정 유형을 나중에 바꾸는 번거로움" 비교가 실제 판단 기준 (8장).

## 5. 기술 스택 (결정)

| 항목 | 선택 | 비고 |
|---|---|---|
| 언어 | **Kotlin 단일** | C/C++(NDK) 직접 작성 없음 — 1인 개발 공수 방어 |
| UI | Jetpack Compose | XML 대비 화면 구현 속도 우위 |
| 플레이어 | Media3(ExoPlayer) 우선 | Kotlin-first API, coroutines/Flow 친화 |
| 크로스플랫폼 | 미도입 | PiP·플로팅 윈도우·SAF 등 B 항목이 플랫폼 표면에 밀착 → 네이티브가 유리 |
| iOS 확장 | 추후 KMP 검토 | 지금은 도입하지 않음. 도메인 로직을 UI에서 분리해두는 수준만 유지 |

**"Kotlin 단일"의 범위**: 직접 작성하는 코드는 전부 Kotlin. 디코더처럼 네이티브 구현이 불가피한 영역은 **미리 빌드된 아티팩트(AAR)를 가져다 쓰는 선까지만** 허용하고, ffmpeg를 직접 빌드하거나 JNI 브릿지를 작성하는 작업은 범위에서 제외.

**주의**: 이 결정이 디코더 라이브러리 선택까지 정하지는 않음. Media3와 libVLC 모두 prebuilt 형태로 Kotlin에서만 사용 가능하므로, 선택 기준은 언어가 아니라 **포맷 커버리지 vs 라이선스·용량**임 (8장 참고).

## 6. MVP 범위 제안 (Android, 1인 개발 기준)

| Phase | 범위 | 목표 |
|---|---|---|
| Phase 1 (MVP) | A 전체 + 자막 기본 지원. 광고·결제 모두 없음 (**PiP 제외**) | 코어 재생 경험 검증 + 리텐션 확보 |
| Phase 2 | 인앱결제 Pro 도입 + B 항목(PiP, 네트워크 연동, 재생목록) 해제 | 수익화 시작 |
| Phase 3 | C(AI 업스케일링/자막 자동생성), 구독 티어 | ARPU 확대 |

**PiP가 Phase 1에서 빠진 이유**: PiP를 Pro 기능으로 확정했기 때문. Phase 1에는 결제 수단이 없어서 Pro 기능을 넣어도 아무도 해제할 수 없고, 무료로 한 번 출시하면 나중에 잠글 때 기존 사용자 반발·평점 하락을 감수해야 함. **무료로 내보낸 기능은 되돌리기 어렵다**는 점이 Phase 배치의 실질적 제약.

**게이팅 구현 시점**: 기능을 먼저 다 만들고 결제 분기는 나중에 붙여도 됨. 단 Phase 1 단계에서 **"이 기능을 쓸 수 있는가"를 판단하는 지점 하나만 인터페이스로 분리**해두고 각 기능이 그것을 통해 묻게 할 것(Phase 1에서는 항상 허용을 반환하는 더미 구현). 이 준비가 없으면 나중에 여러 화면에 흩어진 분기를 일일이 심어야 함. 준비 비용은 인터페이스 하나 수준이라 사실상 0.

## 7. 개발 범위 — 화면 및 기능 (Phase 1)

Phase 1은 **Free 항목만** 구현. Pro 기능은 코드로 미리 만들더라도 빌드에서 노출하지 않음(6장 게이팅 노트 참고).

### 7.1 화면 목록

| # | 화면 | 역할 | 우선순위 |
|---|---|---|---|
| S1 | **라이브러리(홈)** | 기기 내 영상 목록, 최근 재생(이어보기) 상단 노출, 정렬·보기 전환 | P0 |
| S2 | **폴더 탐색** | 저장소 폴더 트리 탐색, 폴더별 영상 목록 | P0 |
| S3 | **플레이어 (세로)** | 재생 화면. 앱의 핵심 — 제스처·컨트롤·자막 렌더링이 모두 여기에 집중 | P0 |
| S3-F | **플레이어 (전체화면·가로)** | 영상이 화면을 채우고 컨트롤이 위에 얹히는 형태. 좌우 제스처(밝기/볼륨), 자동 숨김 | P0 |
| S4 | **자막 설정 시트** | 자막 선택·외부 파일 열기·인코딩 변경·싱크 조정·크기/색 | P0 |
| S5 | **권한 온보딩** | 미디어 접근 권한 요청 및 거부 시 안내 | P0 |
| S6 | **설정** | 재생 기본값, 제스처 감도, 테마/나이트 모드, 취침 타이머, 정보·라이선스 고지 | P1 |
| S7 | **검색** | 파일명 기준 검색 | P2 |

**Pro 도입 시 추가될 화면(Phase 2)**: 네트워크 소스 추가/관리, 비공개 폴더(PIN), 결제·업그레이드 안내. Phase 1에서는 만들지 않음.

### 7.2 기능 단위

**재생 코어 (S3)**
- Media3 플레이어 구성, 하드웨어 가속 디코딩, 오디오 포커스 처리
- 제스처: 좌우 스와이프(탐색), 좌측 상하(밝기), 우측 상하(볼륨), 더블탭(±10초), 핀치(확대)
- 컨트롤: 재생/일시정지, **10초 전/후 이동**, 시크바, 재생속도, 회전·방향잠금, 화면비(맞춤/채움/원본), 트랙 선택(오디오·자막)
- 세로 ↔ 전체화면(가로) 전환. 전체화면은 컨트롤 오버레이 + 자동 숨김, 상·하단 스크림으로 밝은 장면에서의 가독성 확보
- 자막은 영상 프레임 **안쪽**에 렌더링. 컨트롤이 보일 때 시크바와 겹치지 않도록 위로 밀어 올림
- 백그라운드 오디오 재생 및 알림 컨트롤(MediaSession)

**라이브러리 (S1·S2)**
- MediaStore 스캔으로 영상 수집, 썸네일·길이·해상도 메타데이터 추출
- 폴더 트리 구성, 정렬(이름/날짜/크기/길이), 리스트·그리드 전환
- 재생 위치 저장 및 이어보기 — 로컬 DB(Room)

**자막 (S4)**
- 동일 파일명 기준 자막 자동 매칭(.srt/.smi/.ass/.vtt)
- **인코딩 감지 및 수동 변경** — 국내 파일은 `.smi` + CP949 조합이 흔해 실패 시 이탈로 직결되는 지점. 자동 감지 실패에 대비한 수동 변경 경로 필수
- 싱크 오프셋 조정, 글자 크기·색·배경 설정

**기반**
- 권한 처리 (Android 13+ `READ_MEDIA_VIDEO`, 이전 버전 분기)
- 기능 접근 판단 인터페이스 (게이팅 지점 — Phase 1은 항상 허용 반환)
- 설정 영속화 (DataStore), 크래시 리포팅

### 7.3 Phase 1 완료 기준
- 주요 포맷(MP4/MKV/AVI 등)이 실기기에서 하드웨어 가속으로 재생됨
- 자막이 자동으로 붙고, 깨질 경우 인코딩 변경으로 복구 가능
- 앱을 껐다 켜도 이어보기가 동작
- 네트워크 없이 전 기능 동작

## 8. 열린 질문 (다음 논의 필요)
- 사업자 등록 시점 — 앱 출시 전 vs 첫 매출 발생 임박 시점 (광고 제외로 Phase 1 매출이 0이 되면서 후자 쪽 여지가 커짐)
- 광고 완전 배제를 계속 유지할지 — Pro 전환율이 목표 미달일 때의 재검토 트리거를 미리 정의해둘 것
- Free/Pro 경계 미세조정 — A-B 구간 반복(Pro→Free), 색상·필터 편집(Pro+→Pro) 이동 여부
- 개인사업자 vs 청년창업 감면 활용 여부 (해당 시 절세 효과 확인)
- 디코더 라이브러리 선택 — Media3(ExoPlayer) 단독으로 A항목 포맷 커버리지를 채울 수 있는지 확인 필요 (특히 WMV/ASF 계열).
  미달 시 libVLC 검토 → 단 LGPL/GPL 라이선스 조건과 ABI별 APK 용량 증가가 트레이드오프
- AI 기능(Phase 3) 자체 서버 vs 외부 API(예: 업스케일링 SaaS) 비교
- 기존 Pikaworks 포트폴리오(ClipNote 등)와의 연계 여부 — 동일 사업자 명의로 묶을지
